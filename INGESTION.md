# Margate Hedges nightly ingestion — architecture and operational reference

**Site:** margatehedges.co.uk
**Pipeline shape:** SE-shape — Anthropic cloud routine (claude.ai/code scheduled agent)
**Owner:** Richard (claude.ai/code account holder)
**Scaffolded:** 2026-08-12 by Jet, per the hedge-ring rollout (this site's
sister, sandwichhedges.co.uk, was scaffolded 2026-08-11 as the reference
pattern — this file adapts that pattern, it is not a copy of it; this
site's growth surface, JSON-LD shape and structural angle all genuinely
differ, see `TEMPLATES/how-to.md` and `AGENTS.md`).

## What this pipeline is

An Anthropic-hosted scheduled Claude Code routine that runs nightly on
Anthropic's cloud infrastructure. Each run: discovers an uncovered
Margate/Thanet-relevant hedge-care topic + a suitable UK YouTube video (or
other web source) not yet covered by an existing `how-to/*.html` slug,
generates a full **story-led** how-to article matching this site's existing
hand-authored template and JSON-LD shape, commits it to this repo, and
pushes to `main`. The repo's own `.github/workflows/deploy.yml` GH Action
then FTPS-deploys to Krystal automatically — no manual deploy step needed.

This repo had **no** content pipeline before 2026-08-12 — every existing
`how-to/*.html` article (9 of them) was hand-authored. There is no
category-filter JS system on the hub page (unlike sandwichhedges.co.uk) —
`how-to/index.html` is a plain card grid.

**This file documents the pipeline shape. The routine itself (cron, prompt,
schedule) is created and owned separately on Richard's claude.ai/code
account — that setup is out of scope for this scaffolding commit.**

## This site's structural angle: story-led / case-study

Every article generated by this pipeline MUST open with a short, concrete
job-story scenario (a customer call, a specific-feeling situation in a named
Margate/Cliftonville/Westbrook/Garlinge/Northdown/Palm Bay/Westgate-on-Sea
location) before moving into the practical or legal detail. This is the
ring-wide anti-fingerprinting measure for this specific site — see
`TEMPLATES/how-to.md` for the full contract, and `AGENTS.md`'s "Ring
context" section for why this matters (9 sister domains, same underlying
plumbing, Google sees all 9).

## How it works — end-to-end flow (per the SE-shape pattern)

### Stage 1 — trigger
- Scheduled cron on Richard's claude.ai/code account fires the routine.
- The routine spins up a fresh Claude Code session on Anthropic's infra.

### Stage 2 — topic discovery (in-session)
- Session reads the existing `how-to/` folder (9 slugs) to identify covered
  vs uncovered topics against the category list in `config/ingestion.json`.
- Uses web search / WebFetch to find a UK hedge-care/gardening YouTube video
  (or written source) on a plausible uncovered topic.
- Constraints: UK-based creator/source, region UK, qualifying content type
  (not shorts, not compilations). Like-count / subscriber-count used as an
  authority heuristic since the YouTube Data API isn't used (egress to
  youtube.com is often blocked from Anthropic infra — falls back to
  channel-authority heuristic via web search, same as the SE / sandwichhedges
  reference pattern).

### Stage 3 — verification
- Session confirms the source and creator/channel exist and are UK-relevant
  via web search cross-references.
- Records a note about verifiability in the run report.

### Stage 4 — article generation
- Session writes a full HTML article per `TEMPLATES/how-to.md` — the
  authoritative contract for this repo. Key shape: **story-led opening**
  (mandatory), hero + lede, WCA 1981 nesting-season reference wherever
  cutting timing is discussed (reference implementation:
  `how-to/hedge-nesting-season-margate.html`), practical/legal detail in a
  rotating post-story shape (numbered steps / calendar / comparison /
  decision points), closing `.callout` CTA, flat `Article` JSON-LD (not
  `@graph`, not `HowTo` — see `TEMPLATES/how-to.md` §2), `og:image`, correct
  `.section-eyebrow` topic label for the hub card.
- Rotates the post-story macro-structure per the P2 rules in the template
  contract to avoid fingerprintably identical articles even within this
  site's own story-led constant.

### Stage 5 — site updates
- Session adds a new `.card` to `how-to/index.html`'s `.grid.grid-2`, with
  a `.section-eyebrow` label reusing an existing category
  (`Rules & paperwork`, `Species & planting`, `Wildlife & the law`,
  `Owners & managers`, `Reductions & renovation`, `Seasonality`) where it
  genuinely fits.
- Adds the new URL to `sitemap.xml`.
- Adds 1-2 plain in-text `<a href="/how-to/...">` cross-links to genuinely
  relevant existing articles (this site has no `JET-RELATED-GUIDES`
  comment-block convention or related-guides card section — see
  `TEMPLATES/how-to.md` §7 — don't invent one).
- Leaves the footer's "Local guides" column alone (static, hand-curated
  3-link list, not a growing feed).

### Stage 6 — self-audit report
- Session writes `reports/YYYY-MM-DD-content.md` documenting: URLs shipped,
  sources used, creator/authority verification, topic-gap check evidence,
  Margate/Thanet-specificity notes, confirmation the story-led opening
  requirement was met, files modified.

### Stage 7 — commit + push
- Session commits with a `Nightly: add N how-to articles (D Month YYYY)`
  message body listing the shipped articles.
- Includes a `Claude-Session:` trailer for provenance (per SE convention).
- Pushes to `main`.

### Stage 8 — deploy
- Repo's `.github/workflows/deploy.yml` fires on push, FTPS-uploads changed
  files to Krystal (`p125.lon.krystal.io`). No changes needed to this
  workflow. This repo already has a working CI deploy — no manual FTPS step
  is required for routine content pushes.

## Morning audit (second scheduled run)

A second nightly/morning routine audits the full site: hub-grid integrity
(every card links to a real file, every `how-to/*.html` file has a
corresponding hub card), broken links, dead video embeds, SEO completeness
(title/description/canonical/OG/JSON-LD present on every page), story-led
compliance on recent articles, and general relevance. Writes
`reports/YYYY-MM-DD-audit.md`.

## Cost model

- **Claude usage:** counts against Richard's claude.ai/code allowance.
- **Web search / WebFetch:** included in claude.ai/code.
- **YouTube:** used only via WebFetch (no Data API key). Egress-proxy 403 is
  common — routine falls back to channel-authority heuristic.
- **FTPS / hosting:** covered by Krystal LiteSpeed hosting plan.

No YouTube Data API quota to babysit. No local infrastructure dependency.

## Failure modes and resilience

| Symptom | Root cause | Resilience |
|---|---|---|
| YouTube egress blocked (HTTP 403) | Anthropic infra egress policy on youtube.com | Routine falls back to channel-authority heuristic via web search — documented in every run report |
| Fewer than 3 articles shipped | Third topic candidate not verifiable within session | Routine ships what it can verify, reports the shortfall |
| Anthropic infra outage | Anthropic side | Manual re-run via routine dashboard, or wait for next scheduled run |
| New article reads generic, no real story open | Routine drifted off the story-led contract | Morning audit flags it; fix is a rewrite of the opening 2-4 sentences, not a full regenerate |
| New article breaks hub grid (bad link, missing card) | Manual edit slip in `how-to/index.html` | Morning audit checks this; fix is a one-off HTML edit |
