### 9. HTML entity `&amp;` inside JSON-LD script blocks — 5 articles (new this run)

The following articles contain `&amp;` as a literal character sequence inside a `<script type="application/ld+json">` block. Inside `<script>` raw-text elements, the HTML parser does not decode character references, so `&amp;` is passed to the JSON parser as the five-character string `&amp;` rather than as `&`. This means the JSON-LD organization name or description may resolve to "Margate Hedges &amp; Tree Services" rather than "Margate Hedges & Tree Services" in strict parsers, including Google's Rich Results validator.

Affected articles and fields:
- `conifer-hedge-brown-patches-margate.html`: `publisher.name` contains `&amp;`
- `hedge-nesting-season-margate.html`: `description` contains `Sandwich &amp; Pegwell Bay Ramsar`
- `hedge-width-reduction-margate.html`: `publisher.name` contains `&amp;`
- `hedgerow-management-regulations-2024-margate-kent.html`: `publisher.name` contains `&amp;`
- `tamarisk-hedge-care-margate.html`: both `author.name` and `publisher.name` contain `&amp;`

Not in auto-fix scope. Recommend batch replacement of `&amp;` with `&` inside all JSON-LD blocks as a deliberate template fix. The correct character inside a JSON-LD script element is a literal `&`.
